# Recursos públicos de documentos

El build público solo admite documentos con `status: "published"` y `visibility: "public"`. Las imágenes del editor usan `/img/documents/<documentId>/<nombre>.webp` (el flujo del CMS también acepta `.png` y `.jpg`). La publicación lee el árbol MDX para encontrar `DocumentImage`, imágenes Markdown y sus hijos dentro de `DocumentGallery`; también admite `imageSrc` del documento. Cada referencia debe pertenecer al ID del documento, tener un nombre simple y existir como archivo regular. Una imagen no referenciada no se copia.

El [PDF Asset Workflow del CMS, PR #15](https://github.com/sukumidev/hallyura-cms/pull/15) guarda archivos en `static/handouts/<documentId>/<nombre>-<hash de 10 hex>.pdf`, pero **todavía no exporta un manifest ni una propiedad JSON de PDF**. El [PR #16 del CMS](https://github.com/sukumidev/hallyura-cms/pull/16) añade un bloque MDX `DocumentPdf` cuyo contrato acepta cualquier nombre slug `.pdf` dentro de esa carpeta. El build reconoce su atributo literal `src` y también enlaces Markdown explícitos. Publica únicamente los PDFs referenciados explícitamente en el MDX o Markdown de documentos públicos; los archivos que solo estén presentes en una carpeta no se copian. Si se versiona en Git un PDF sin referencia pública aprobada, el build falla. Un documento público puede compartir un recurso cuyo propietario también sea público. Una carpeta de un documento privado, archivado o desconocido nunca se copia. No se necesita un manifiesto adicional para estos bloques: se inspeccionan las referencias MDX mediante AST sin ejecutar el documento. El almacenamiento de PDFs privados sigue fuera del alcance actual.

Los archivos tienen un límite público de 25 MiB por recurso. La Wiki comprueba la firma, el cierre y la referencia cruzada del PDF antes de copiar sus bytes intactos. El CMS aplica su propio límite preventivo de 24 MiB. La comprobación de estructura de la Wiki no sustituye la validación completa con `pdf-lib` del CMS.

**Privacidad del repositorio:** excluir un PDF del build no lo protege si ya se subió al repositorio público. El build bloquea cualquier PDF versionado bajo `static/` fuera de la ruta aprobada o cuya carpeta pertenezca a un documento no público o desconocido. Los PDFs privados deben permanecer fuera del repositorio público; el flujo actual del CMS los conserva pendientes en el navegador y no ofrece almacenamiento privado permanente.

La detección de imágenes en `DocumentGallery` quedará disponible en el lector cuando se integre [el PR editorial de la Wiki](https://github.com/sukumidev/dnd-kpop-wiki/pull/49). Esta política de publicación puede integrarse desde `main` de forma independiente.
